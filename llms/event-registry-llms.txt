# Event Registry (NewsAPI.ai)

> News intelligence API. Search global news articles, retrieve deduplicated event clusters,
> resolve named entities to URIs, and read sentiment and category enrichment across 150,000+
> sources in 60+ languages, with a historical archive back to 2014.

GENERATED by API Evangelist on 2026-08-13 from this repository's apis.yml and artifacts.
Event Registry does NOT publish an llms.txt: https://newsapi.ai/llms.txt and
https://eventregistry.org/llms.txt both return the site's single-page-application HTML shell,
byte-identical to the shell served for a known-nonexistent path. Treat this file as API
Evangelist's summary, not the provider's.

## How to call it

- Base URL: https://eventregistry.org/api/v1
- Every operation is a POST with a JSON body. There are no GET endpoints and no resource URLs.
- Auth: an `apiKey` field inside the JSON body (a query parameter of the same name also works).
  Get one at https://newsapi.ai/register — free plan, 2,000 searches, no credit card.
- Entity filters take opaque URIs, not names. Resolve a name to a URI with a suggest call
  FIRST, then pass the URI. Almost every real query is therefore a two-call sequence.
- Concurrency is capped at 5 simultaneous requests per account. Exceeding it returns HTTP 503
  immediately; requests are not queued. Make calls sequentially.
- Cost signal: responses carry `req-tokens` (tokens this request cost) and
  `x-ratelimit-remaining` (tokens left). There is no standard RateLimit header and no
  Retry-After.

## Operations

Articles
- searchArticles — POST /article/getArticles — search articles by concept, source, category,
  date, language, sentiment.
- getArticleDetails — POST /article/getArticle — full detail for up to 100 article URIs.
- getTopicPageArticles — POST /article/getArticlesForTopicPage — articles from a saved topic page.

Events (clusters of articles about one real-world happening — polled, not pushed)
- searchEvents — POST /event/getEvents
- getEventDetails — POST /event/getEvent
- getTopicPageEvents — POST /event/getEventsForTopicPage

Suggest (name to URI resolution — call these before filtering)
- suggestConcepts — POST /suggestConceptsFast
- suggestCategories — POST /suggestCategoriesFast
- suggestSources — POST /suggestSourcesFast
- suggestLocations — POST /suggestLocationsFast
- suggestAuthors — POST /suggestAuthorsFast

Usage
- getApiUsage — POST /usage — tokens used and remaining for the current key.

## Token efficiency (the provider's own recommended pattern)

suggest -> scan -> triage -> retrieve.
1. suggest({type: "concepts", prefix: "<name>"}) to get a URI.
2. search_articles({conceptUri, articlesCount: 100, articleBodyLen: 0,
   isDuplicateFilter: "skipDuplicates"}) — titles only, no bodies. Cheap.
3. Pick the URIs that matter.
4. get_article_details({articleUri: [...up to 100...]}) for full text on just those.

Costs: recent article search 1 token; historical article search 5 tokens per year queried;
recent event search 5 tokens; historical event search 20 tokens per year. Cache suggest
results — they are stable and the provider's own server caches them for 24 hours.

## Errors

- 400 invalid_param, 401/403 auth_error, 404 not_found, 429 rate_limit (quota — wait, do not
  hammer), 503 concurrent_limit (the 5-request cap), 5xx api_error.
- Envelope is a bespoke {error, message} JSON object. NOT RFC 9457 problem+json.
- Only 401 and 429 are declared in the OpenAPI; the rest come from the provider's own MCP
  error classifier.

## What does NOT exist

No webhooks, no streaming, no push. No GraphQL. No gRPC. No OAuth or OIDC. No CLI. No
embeddable UI components. No status page. No security.txt or vulnerability disclosure
program. No trust center or published certifications. No test/sandbox environment — the
"sandbox" at newsapi.ai/documentation/sandbox is a browser query builder that spends real
quota against live data.
